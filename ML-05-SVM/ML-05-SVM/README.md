# 🐒 vs 🧑 — สอนให้เครื่องแยกคนกับลิงออกจากกัน

> โปรเจกต์ computer vision แบบคลาสสิก ไม่มี neural network ไม่ต้องใช้ GPU
> มีแค่ gradient, เรขาคณิต และ Support Vector Machine ที่พยายามอย่างเต็มที่

**สถานะปัจจุบัน: Accuracy 80.0%** (Python 3.11 · scikit-learn · OpenCV)

---

## สรุปสั้นๆ

โปรเจกต์นี้เทรน SVM ให้แยกภาพว่าเป็น **คน** หรือ **ลิง** โดยใช้ feature
แบบดั้งเดิม (hand-crafted) ล้วนๆ ไม่มี deep learning เข้ามาเกี่ยวข้องเลย
ระหว่างทางโมเดลเปลี่ยนจาก *"เดาสุ่มๆ"* ไปเป็น *"มองเห็นจริง"* และ
กระบวนการ debug ที่เกิดขึ้นระหว่างทางน่าสนใจกว่าตัวเลข accuracy สุดท้ายเสียอีก

**ผลลัพธ์สุดท้าย: 80.0% accuracy สมดุลทั้งสอง class**

---

## ทำไมเรื่องนี้ถึงยากกว่าที่คิด

ถ้าใช้ deep learning เรื่องนี้แทบจะเป็นปัญหาที่แก้ได้ง่ายๆ — ป้อนภาพเยอะพอ
CNN ก็จะแยกขนกับผิวหนังได้เอง แต่โปรเจกต์นี้เลือกทำแบบ *"เก่าแก่"* โดยตั้งใจ:

1. แปลงทุกภาพให้เป็น **HOG (Histogram of Oriented Gradients)** feature
   vector — เปรียบเหมือนลายนิ้วมือของขอบและรูปทรงในภาพ
2. เอาลายนิ้วมือนั้นไปป้อนให้ **SVM** ซึ่งจะหาเส้นแบ่งที่ดีที่สุดระหว่าง
   "ทรงคน" กับ "ทรงลิง" ใน feature space นั้น

ไม่มีการเรียนรู้ feature เอง ไม่มี backpropagation โมเดลรู้แค่สิ่งที่เรา
ป้อนให้เท่านั้น — ซึ่งทำให้มันเป็นวิธีที่ดีมากในการ *เข้าใจ* ว่าเกิดอะไร
ขึ้นจริงๆ แทนที่จะเชื่อ black box เฉยๆ

---

## การสืบสวน 🔍

pipeline เวอร์ชันแรกได้ **54.5% accuracy** — แทบไม่ต่างจากการโยนเหรียญ
ที่แย่กว่านั้นคือมันไม่ได้ผิดแบบสุ่มๆ ด้วย — มันแทบจะตัดสินใจไปแล้วว่า
ทุกอย่างคือลิง

```
Confusion Matrix (เวอร์ชันแรก)
              ทายเป็น
              Human  Monkey
จริงคือ Human    2      19    😬
จริงคือ Monkey   1      22
```

นี่ไม่ใช่ noise — นี่คือโมเดลที่ยอมแพ้แล้วเลือกทายฝั่งเดียวไปเลย
ต่อไปนี้คือขั้นตอนการตามหาสาเหตุ ทีละสมมติฐาน

### ผู้ต้องสงสัยที่ 1: PCA ทิ้งส่วนสำคัญไป

pipeline เดิมบีบอัด HOG feature ให้เหลือ 150 มิติด้วย PCA ก่อนเทรน
ปัญหาคือ PCA เลือกเก็บสิ่งที่มี *variance สูงสุด* ไว้ — แต่ variance
ไม่เท่ากับ *ความเกี่ยวข้องกับงาน* เสมอไป ปรากฏว่าตัวการหลักที่ทำให้เกิด
variance ใน dataset นี้ไม่ใช่ "คนกับลิง" แต่เป็น "พื้นหลังรกๆ กับพื้นหลัง
เบลอๆ" ต่างหาก PCA เลยเก็บส่วนนั้นไว้ แล้วทิ้งสัญญาณที่ละเอียดอ่อนกว่า
อย่างรูปร่างจริงของ subject ไปแทน

**ทางแก้:** เทรนตรงกับ HOG vector เต็มๆ ไม่ผ่าน PCA
**ผลลัพธ์:** 54.5% → **70.5%** 📈

### ผู้ต้องสงสัยที่ 2: hyperparameter ตั้งค่าผิด?

คำถามถัดมาที่ชัดเจน — SVM ตั้งค่าไม่ดีหรือเปล่า? ใช้ `GridSearchCV`
ไล่ลองค่า `C` และ `gamma` หลายชุด พร้อม 5-fold cross-validation
เพื่อหาค่าที่ดีที่สุด

**ผลลัพธ์:** 68.2% — พอๆ กับก่อนหน้าในทางสถิติ หรืออาจจะแย่กว่านิดหน่อยด้วยซ้ำ

นี่คือ negative result ที่มีประโยชน์ที่สุดของโปรเจกต์นี้ — มันพิสูจน์ว่า
คอขวดไม่เคยอยู่ที่การตั้งค่าของโมเดลเลย การปรับจูนบนสัญญาณที่พังอยู่แล้ว
ไม่ได้ช่วยแก้สัญญาณนั้นให้ดีขึ้น

### ผู้ต้องสงสัยที่ 3: ตัว dataset เอง

ต้นตอที่แท้จริง: สอง class นี้ไม่ได้ต่างกันแค่ subject เท่านั้น แต่ต่างกัน
ที่ **สไตล์การถ่ายภาพ** ด้วย ภาพคนส่วนใหญ่เป็นภาพมุมกว้าง คนตัวเล็กจิ๋ว
อยู่ในฉากที่รก ส่วนภาพลิงเป็นภาพระยะใกล้แบบสัตว์ป่าที่มีพื้นหลังเบลอนุ่มๆ
HOG feature เลยแอบวัด "พื้นหลังรกหรือเบลอ" แทนที่จะวัดตัวงานจริงๆ

**ทางแก้:** คัดภาพให้สอดคล้องกันมากขึ้น เพื่อให้ subject ครองเฟรมจริงๆ
ทั้งสอง class
**ผลลัพธ์:** 70.5% → **80.0%** พร้อม precision และ recall ที่สมดุลกัน
พอดี **0.80 / 0.80** ทั้งสอง class

```
Confusion Matrix (เวอร์ชันสุดท้าย)
              ทายเป็น
              Human  Monkey
จริงคือ Human    16      4    ✅
จริงคือ Monkey    4     16
```

## สิ่งที่ได้เรียนรู้จริงๆ

| บทเรียน | ข้อคิด |
|---|---|
| โมเดลที่ผิดอย่างมั่นใจมักมี "เหตุผล" | confusion matrix เผยอคติได้ ไม่ใช่แค่บอก error rate |
| การลด dimension ไม่ได้ดีเสมอไป | PCA optimize เพื่อ variance ไม่ใช่เพื่องานที่เราต้องการ |
| การหา hyperparameter มีขีดจำกัด | มันแก้สัญญาณที่อ่อนแอโดยพื้นฐานไม่ได้ |
| คุณภาพข้อมูล สำคัญกว่า การปรับจูน algorithm | จุดที่ได้กำไรมากที่สุดมาจากข้อมูลที่ดีขึ้น ไม่ใช่คณิตศาสตร์ที่ดีขึ้น |

## Pipeline สรุป 5 ขั้นตอน

1. **โหลดข้อมูล** — อ่านภาพจาก `PetImages/<ClassName>/` แล้ว resize +
   แปลงเป็น grayscale โดย label ของ class มาจากชื่อโฟลเดอร์โดยตรง
2. **สกัด HOG feature** — แปลงแต่ละภาพให้เป็นลายนิ้วมือของ gradient
   แทนที่จะใช้ raw pixel ตรงๆ
3. **แบ่งข้อมูล** — train/test แบบ stratified สัดส่วน 80/20
   (`random_state=42` เพื่อให้ทำซ้ำได้)
4. **scale + เทรน** — `StandardScaler` fit กับ training data เท่านั้น
   (ไม่แอบดู test set) แล้วเทรน SVM แบบ RBF kernel
5. **ประเมินผล** — accuracy, precision/recall ต่อ class, plot confusion matrix
